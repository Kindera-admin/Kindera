# My NGOs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Staff assign NGO partner cards to one or more companies. Those cards are visible only to that company's SPOCs and employees, on a read-only My NGOs page. An NGO login generated from such a card can only create events for one of its companies.

**Architecture:** This extends the existing `NGOPartner` model and its actions in `src/app/actions.js`. Visibility rules live in a new `src/lib/ngo.js` that uses `src/lib/company.js`. Event visibility itself is unchanged: an NGO event just carries a `companyId`.

**Tech Stack:** Next.js 15 App Router server actions, Mongoose 8, React 19, Tailwind 4 + shadcn/ui, `xlsx` (already a dependency), Vitest + mongodb-memory-server.

**Spec:** docs/superpowers/specs/2026-10-12-my-ngos-design.md

## Global Constraints

- JavaScript only. Use the `@/` alias for `src/`.
- Every company comparison goes through `src/lib/company.js`. Every NGO-card visibility rule goes through `src/lib/ngo.js`.
- Only staff (`admin`, `employee`) create, edit, import, delete, or generate logins for NGO cards. Everyone else is refused with "Only admins and employees can manage NGO partners", and nothing changes.
- Validate client-supplied ids with `isValidObjectId` before using them. Never return CastError or raw error text.
- Fail closed: if in doubt, the NGO is not shown and the event is not created.
- Tests for denied paths assert that nothing changed in the database.
- Commit as the repo identity. No Co-Authored-By or AI attribution lines.
- Record user-facing changes in `docs/FEATURES.md` (Task 4).

- Create: `src/lib/ngo.js`, `tests/lib/ngo.test.js`
- Modify: `tests/helpers/factories.js` (add `makePartner(fields)`)

**Interfaces (produces):**
- `NGOPartner.companyIds: [ObjectId ref 'Company']`, default `[]`.
- `NGOPartner.loginUserId: ObjectId ref 'User'`, default `null`.
- `User.ngoPartnerId: ObjectId ref 'NGOPartner'`, default `null`.
- `partnerVisibilityFilter(caller)` returns a Mongo filter:
  - staff → `{}`;
  - `isCorporate(caller)` with a `companyId` → `{ $or: [{ companyIds: { $size: 0 } }, { companyIds: caller.companyId }] }`;
  - otherwise → `{ companyIds: { $size: 0 } }`.
- `myNgosFilter(caller)`:
  - `isCorporate(caller)` with a `companyId` → `{ companyIds: caller.companyId }`;
  - otherwise → `null`, and callers must refuse.
- `ngoEventCompanies(ngoUser, partner)` returns an array of allowed values:
  - `ngoUser.ngoPartnerId` null → `[null]`;
  - partner missing → `[]`;
  - partner with `companyIds` empty → `[null]`;
  - otherwise → `partner.companyIds` as strings.
- `makePartner(fields)` creates an NGOPartner. Defaults are `name: 'Partner'` and `description: 'desc'`, merged with the fields passed in.

### Task 2: NGO card actions

**Files:**
- Modify: `src/app/actions.js`:
  - the NGO Partners section: `getAllNGOPartners`, `createNGOPartner`, `updateNGOPartner`, `deleteNGOPartner`;
  - new `getMyNGOs`, `importNGOPartners`, `generateNGOLogin`;
  - `registerUser`, the `role === 'ngo'` branch.
- Create: `tests/actions/ngos.test.js`

**Interfaces (produces):**
- **`getAllNGOPartners()`**
  - Scoped by `partnerVisibilityFilter(await getCurrentUser())`. It still works logged out and then shows public cards only.
  - Items are the existing shape plus `companyIds: string[]` and `companyNames: string[]` (batched via `getCompaniesByIds`).
  - Staff also get `loginUsername: string|null`.
- **`getMyNGOs()`** returns `{ success, partners }`.
  - Partners have the same shape without `loginUsername`, plus `upcomingEvents: number`.
  - `upcomingEvents` counts events with `createdBy` = the card's `loginUserId`, `companyId` = the caller's company, and `date >= now`.
  - Refused unless `myNgosFilter` is non-null.
- **`createNGOPartner(formData)` / `updateNGOPartner(id, formData)`** read `companyIds` as a JSON array string; missing means `[]`.
  - Every id must pass `isValidObjectId` and match an active Company (`Company.countDocuments({ _id: { $in }, status: 'active' })` equals the count of unique ids).
  - Otherwise refuse with "Choose active companies only".
  - `updateNGOPartner` validates `id`.
- **`importNGOPartners(rows, companyIdsJson)`**
  - Staff only. Accepts 1–500 rows; anything else is refused.
  - Companies are validated as above.
  - Each row is trimmed. A row missing `name` or `description` is skipped with its row number and reason. `programs` is split on newlines or `;`.
  - Uses `NGOPartner.insertMany(valid, { ordered: false })`. Catch a bulk write error, count the inserted rows, and report the failures generically.
  - Returns `{ success: true, created: n, skipped: [{ row, reason }] }`.
- **`generateNGOLogin(partnerId)`**
  - Staff only, with a valid id. Refused if the card is missing or already has `loginUserId`.
  - Creates the User:
    - `role 'ngo'`, `status 'approved'`;
    - `name` and `ngoName` = the card name;
    - `ngoId` = `NGO-` plus 8 uppercase hex characters, unique;
    - `username` = slug(name, max 20) + `-` + 4 random digits, retried on collision up to 5 times;
    - `password` = 10 random URL-safe characters (crypto), which the existing pre-save hook hashes;
    - `ngoPartnerId` = the card.
  - Sets `partner.loginUserId` and returns `{ success, username, password }`.
- **`deleteNGOPartner(id)`**
  - Validates the id. If a login is linked, sets it to `status 'rejected'` and `ngoPartnerId: null`.
- **`registerUser`**: for `role 'ngo'`, store `ngoName = name`.

- [ ] Write `tests/actions/ngos.test.js`. Cover every bullet of spec §7 except the NGO-event bullets (Task 3 adds those). That includes:
  - `login()` working with the generated password;
  - spocA and spocA2 getting identical `getMyNGOs` results;
  - spocB not seeing A's cards;
  - a public card visible to everyone and an A-only card hidden from a volunteer or logged-out caller;
  - each staff-only action refused for spocA, memberA and volunteer, with no change in counts;
  - invalid, unknown and archived company ids refused;
  - import reporting skipped rows.
- [ ] Run it and watch it fail. Implement. Watch it pass. Run the full suite and the build.

### Task 3: NGO events for a company

**Files:**
- Modify: `src/app/actions.js` (`createEvent`, `role === 'ngo'` path), `src/app/events/create/page.js`, `src/app/events/create/CreateEventForm.js`
- Modify: `tests/actions/ngos.test.js` (add a `describe('NGO events')` block)

**Interfaces:**
- **`createEvent`** for `role 'ngo'`:
  - Load `NGOPartner.findById(user.ngoPartnerId)` when it is set, and compute `allowed = ngoEventCompanies(user, partner)`.
  - If `allowed` is `[]`, refuse with "Your NGO account is no longer active".
  - If `allowed` is `[null]`, set `companyId: null` and ignore the form value.
  - Otherwise `formData.get('companyId')` must be a valid id inside `allowed`; if not, refuse with "Choose which company this event is for". Set `companyId` to it.
- **`events/create/page.js`**: for a linked NGO with company cards, pass `companyChoices: [{ _id, name }]`, resolved server-side via `getCompaniesByIds`. Otherwise pass `[]`.
- **`CreateEventForm`** takes `companyChoices = []`.
  - When it is non-empty, show a required "Company" `<select>` with a placeholder "Choose a company", named `companyId`, styled like the form's other inputs.
  - Below it, add the helper text "Only this company's team will see the event."

- [ ] Add tests:
  - a linked NGO creating for A gets `companyId` A;
  - memberA can see the event, while memberB and a volunteer cannot (use `getEvents`);
  - missing, B and malformed company values are refused with no Event created;
  - an unlinked NGO creates a public event;
  - after the card is deleted, its login is refused.
